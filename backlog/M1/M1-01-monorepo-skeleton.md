## Decisions already taken (PO, 2026-09-29)
- Bundle identifier and Android package: `app.rustle`. URL scheme: `rustle`. App name: Rustle.
- Package manager: npm workspaces (`app`, `packages/shared`, `evals`); Node LTS pinned in `.nvmrc`; one root `npm run typecheck`, `npm test`, `npm run lint`, `npm run eval`.
- Expo SDK: the current stable SDK, TypeScript strict, expo-router, development builds (never Expo Go).
- Tests: Jest (`jest-expo` preset) for the app, plain Jest for `packages/shared` and `evals`; a single root `npm test` runs all workspaces.
- Dependencies allowed in this ticket, nothing else: `expo-router`, `expo-dev-client`, `expo-splash-screen`, `expo-secure-store`, `expo-localization`, `expo-font`, `@shopify/react-native-skia`, `react-native-mmkv`, `@tanstack/react-query`, `@supabase/supabase-js`, `zod`, `husky`, `jest`, `jest-expo`, `@types/jest`, `typescript`, `eslint` with `eslint-config-expo`.
- Supabase: no dev project exists yet. `supabase/config.toml` is written for a project named `rustle-dev`; `app/.env.example` documents `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`; `.env*` files are git-ignored except `.env.example`.

## Risks and notes
- expo-apple-targets and native folders should be scaffolded but empty; don't fight Xcode here. Do not run `expo prebuild` and do not commit `ios/` or `android/` (they are generated by EAS).
- packages/shared must be pure ESM with no Node built-ins so Deno can import it. Prove it: `supabase/functions/_shared/shared-smoke.ts` imports the glossary constants through `supabase/functions/deno.json` (an import map entry `@rustle/shared/` → `../../packages/shared/`) and `deno check` passes on it. If `deno` is not on the PATH, say so in the report and mark criterion 6 unverified.
- packages/shared exports the glossary constants (docs/00 table: `note`, `delivery`, `reply`, `warm_note`, event prefixes `board_note_`, `delivery_`, `reply_`, `warm_note_`) and the design tokens from docs/20 §13 verbatim in `packages/shared/tokens.ts`. Do not define the `life_areas` or delivery-intent enums here: the docs still disagree on their values (doc 05 §3 vs doc 08 §5.4; doc 00 vs doc 07 §3 vs doc 08 §3.3) and they land with M1-02 once reconciled. Leave a typed placeholder with a TODO pointing at M1-02.
- CI (`.github/workflows/ci.yml`) runs `npm ci`, typecheck, lint and tests on every PR and on `main`; a separate `eval.yml` runs `npm run eval` only when files under `supabase/functions/_shared/prompts/**` or `evals/**` change (it calls the Claude API and needs the `ANTHROPIC_API_KEY` secret). `npm run eval` may be a stub that exits 0 with "no prompts yet" until M1-07. Doc 21 §0.1 says every PR; the lead reconciles doc 21 to this.
- Secret scanner: `gitleaks` in a husky pre-commit hook (`gitleaks protect --staged`), plus a gitleaks step in CI. If `gitleaks` is not installed on the machine, the hook must print one line and exit 0 rather than block commits; CI still runs it.
- Region: Supabase Edge Functions do not take a region in `config.toml`. Do not invent a config key. Record in the report which mechanism pins execution to Canada Central (project-level setting at creation, or the `x-region` header on invocations) and leave a one-line TODO in `supabase/config.toml` for M1-02. No note text is processed outside Canada (doc 07 §8, Law 25).
- `app/app/_layout.tsx` is a minimal root layout that renders a placeholder screen with no user-visible text other than the word "Rustle"; M1-04 replaces it with the tab skeleton. No colours, no strings, no styling here.
- `web/README.md` and `scripts/README.md` are placeholders (one line each) so the layout from docs/07 §11 exists; nothing else in those folders.
- The `.gitignore` covers `node_modules`, `.expo`, `ios/`, `android/`, `.env*` (not `.env.example`), `*.log`, `.DS_Store`, `dist`, `coverage`.
